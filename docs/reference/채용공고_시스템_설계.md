# 채용공고 검색·추천 시스템 설계

작성 2026-10-02 · 기준 브랜치 `feature/jobs` · 배포 프리뷰 https://tikle-git-feature-jobs-cau-et.vercel.app

취준생이 사람인·잡알리오·기관 홈페이지를 돌아다니며 찾던 채용공고를 한 화면에 모으고,
프로필(목표 직무·거주지·학력)에 맞는 공고와 마감 임박 공고를 먼저 보여주는 기능.
티끌의 기존 축(취업 전 정책 ↔ 일정 ↔ 취업 후 시뮬레이션)에 "채용"을 잇는 가운데 조각이다.

---

## 1. 아키텍처 — 어댑터는 소스별로 많이, 도구는 도메인별로 적게

```
[소스 어댑터]            [정규화·적재]            [조회 계층]              [화면]
사람인 오픈API ──┐                                /api/jobs/search   →  /app/jobs (검색 페이지)
잡알리오 API   ──┼→ 공통 스키마 변환 → job_postings ─ /api/jobs/recommend →  메인 좌측 "채용 공고" 탭
(고용24 예정)  ──┘   (코드가 결정)     (Supabase)                          (추천 + ⏰ 마감 임박)
```

- 소스마다 분류·지역 표기가 달라서 **수집 시점에 코드가 하나의 스키마로 정규화**한다.
  지역 → 표준 시도명(normalizeSido, 정책 파이프라인과 동일 함수), 직무 → NCS 대분류 25종
  (24종 + 잡알리오 확장 "연구"), 마감 → date(상시·채용시 마감은 null).
- 사용자 트래픽은 정부·사람인 API가 아니라 **자체 DB를 조회**한다. 외부 API 호출 한도는
  수집(일 1회)에만 쓰이므로 방문자 수와 무관하다.
- 에이전트/챗봇 확장 시에도 도구는 소스별이 아니라 도메인별 1벌(search_jobs(org_type, ncs,
  region, keyword))로 유지한다 — 소스 추가가 프롬프트·도구 변경을 일으키지 않게.

### 데이터 소스와 호출 한도

| 소스 | 대상 | 방식 | 한도 | 1회 수집 호출 | 상태 |
|---|---|---|---|---|---|
| 잡알리오 (기획재정부 공공기관 채용정보, data.go.kr) | 공공기관·공기업·출연연 (의무공시) | 접수 중 전수 스냅샷 | 1,000회/일 | ~6회 (100건×페이지) | **가동 중** (496건) |
| 사람인 오픈API | 민간 기업 | 최신 1,100건 부분 스냅샷 | 일 쿼터 | ~10회 | 어댑터 완성, 키 승인 대기 |
| 고용24(워크넷) | 고용부 등록 민간 공고 | 전수 | — | — | 확장 예정 |

민간 플랫폼(잡코리아·자소설닷컴 등) 크롤링은 약관·데이터베이스권 침해 소지가 있어 배제.
공식 API + 의무공시 채널 조합으로 합법적 커버리지를 만든다.

## 2. 최신화 알고리즘 (매일 자동)

구현: `src/lib/collectJobs.ts` → `refreshJobPostings()` —
수동 실행(`npx tsx scripts/collect_jobs.mts`)과 크론(`/api/cron/discover`, **매일 06:00 KST**,
정책 수집과 같은 크론에 합류 — Vercel Hobby는 크론 2개 제한)이 같은 함수를 쓴다.

공고의 생애주기 4가지 경우를 각각 이렇게 처리한다:

| 상황 | 처리 | 방법 |
|---|---|---|
| **새 공고 게시** | 다음 수집에서 자동 편입 | job_id("소스:원본ID") 기준 upsert — 없던 ID는 insert |
| **기존 공고 변경** (마감 연장·내용 수정) | 최신 값으로 덮어씀 | 같은 job_id upsert가 전 컬럼 갱신 |
| **마감 경과** | 모든 화면에서 자동 제외 | 조회 계층이 `deadline ≥ 오늘 OR 상시` 필터 (행 삭제 불필요) |
| **철회·조기마감** (마감 전인데 공고가 내려감) | 삭제 | **스냅샷 비교**: 전수 소스(잡알리오)에서 "마감 전 + 이번 수집에 없음" = 철회로 간주, 삭제. 부분 수집 소스(사람인)는 오탐 위험이 있어 삭제하지 않고 마감일로 자연 소멸 |

사용자 화면 반영:
- 검색 페이지·추천 API는 DB를 직접 보므로 수집 직후부터 새 공고가 보인다.
- 메인 좌측 추천 카드는 **하루 단위 캐시**(localStorage, 날짜가 바뀌면 재계산)라 아침 수집 →
  당일 첫 접속에 새 공고 기준으로 추천된다. 🔄 버튼으로 즉시 재계산 가능.
- 마감 임박(⏰ D-7)은 저장된 마감일로 매 렌더마다 계산되므로 수집과 무관하게 매일 갱신된다.

한도 검증: 일 1회 수집 = 잡알리오 ~6회 호출 (한도 1,000회/일의 0.6%). 시간당 수집으로
올려도 ~144회로 여유.

## 3. 매칭(추천) 알고리즘 — 규칙 점수화 + LLM 재순위 하이브리드

구현: `/api/jobs/recommend`. 원칙은 서비스 전체와 동일 — **숫자·사실은 코드가, 의미 판단·해설은 AI가**.

### 1단 — 하드 필터 (코드)
- 마감 전(상시 포함) 공고만
- 거주지 시도 공고 + 전국 공고
- 목표 직무(자유 텍스트)를 **키워드 사전 규칙**으로 NCS 코드로 변환
  (예: "데이터 분석" → 정보통신·경영사무·연구. LLM이 직무 분류를 추측하지 않음)

### 2단 — 가중치 점수화 (코드, 결정적)

| 항목 | 점수 |
|---|---|
| 주력 직무분야 일치 | +4 (부분야 +2) |
| 거주지·근무지역 일치 | +3 (전국 +1) |
| 신입 지원 가능 | +2 / "경력만" **−6** |
| 학력 요건 충족 | +1 / 미충족 **−5** |
| 마감 임박 | D-7 +3, D-14 +2 |
| 정규직 | +1 |
| 직무 키워드가 제목·본문에 등장 | +2 |

0점 이하 탈락, 점수순 **상위 25건**만 3단으로.

### 3단 — LLM 재순위·이유 생성 (Groq, JSON 모드)
- 후보 요약 + 프로필을 주고 최대 6건 선별, 건별 "왜 맞는지" 1문장 + 관련도 0~100.
- 2단이 "조건 충족"을 거른다면 3단은 **의미**를 읽는다 — NCS가 달라도 공고 내용이 직무와
  맞는 경우(예: "기록물관리·데이터 관리" 공고 ↔ 데이터 분석 지망)를 집어낸다.

### 가드레일 (신뢰성)
- 후보 목록에 없는 job_id는 폐기 (환각 차단), 관련도 55 미만 제외
- LLM 실패·빈 응답 시 2단 점수순 6건으로 **폴백** (이유는 규칙 문구 자동 생성 — 서비스 무중단)
- 마감일·D-day 계산, 마감 임박(D-7) 선정은 전부 코드
- 모든 카드에 공고 원문 링크 — 최종 확인은 공식 공고에서

검색 페이지(/app/jobs)는 LLM 없이 100% 코드 필터(지역·NCS·학력·경력·키워드, 마감 임박순)이고,
첫 진입 시 프로필 값으로 자동 검색된다.

### 왜 학습 모델이 아닌가
사용자 행동 데이터가 없는 콜드스타트에서 학습 기반 추천은 근거가 없다. 규칙+LLM 하이브리드는
모든 추천에 **설명 가능한 이유**가 붙어 금융·공공 심사 기준에 맞는다. 담기·지원 행동이 쌓이면
임베딩 유사도(pgvector)와 행동 가중치를 얹는 것이 고도화 경로.

## 4. AI 사용 지점 요약

| 단계 | 기술 | AI가 하는 것 | AI가 못 하게 막은 것 |
|---|---|---|---|
| 수집·정규화 | 코드 (어댑터) | — | 분류·지역·날짜 추측 |
| 직무→NCS 매핑 | 키워드 사전 (코드) | — | 직무 분류 추측 |
| 후보 압축 | 가중 점수 (코드) | — | — |
| 최종 선별 | LLM (Groq gpt-oss-20b) | 의미 적합도 판단 + 추천 이유 | 없는 공고 생성(ID 검증), 날짜 계산, 55점 미만 노출 |

## 5. 파일 지도

| 파일 | 역할 |
|---|---|
| `src/lib/collectJobs.ts` | 수집·정규화·upsert·철회정리 (크론·스크립트 공용) |
| `scripts/collect_jobs.mts` | 수동 수집 실행기 |
| `src/app/api/cron/discover/route.ts` | 매일 06:00 정책+채용 동시 최신화 |
| `scripts/sql_job_postings.sql` | job_postings DDL |
| `src/data/ncs.ts` | NCS 25종, 직무→NCS 매핑, 학력·경력 판정, D-day |
| `src/app/api/jobs/search/route.ts` | 조건 검색 (코드 필터) |
| `src/app/api/jobs/recommend/route.ts` | 프로필 추천 (점수화+LLM) |
| `src/app/app/jobs/page.tsx`, `src/components/app/JobsView.tsx` | 검색 페이지 |
| `src/app/app/page.tsx` (채용 탭) | 메인 좌측 추천 + 마감 임박 |

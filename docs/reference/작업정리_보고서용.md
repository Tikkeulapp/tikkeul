# 티끌(Tikkeul) — 작업 정리 (보고서용)

> 2026 금융 AI Challenge 출품작. 작업 기간 2026-09-02 ~ 09-05. 배포 URL: https://tikle.vercel.app

---

## 1. 서비스 개요

**한 줄 정의**: 취업준비생의 프로필(설문 + 마이데이터)과 일정을 전국 청년·취준 정책과 대조해, 받을 수 있는 혜택을 AI가 먼저 찾아 절약액까지 계산해주는 **취업 준비 비용 절감 AI Agent**.

**슬로건**: "영끌 아닌 티끌" — 취업 준비하며 쓸 돈, 몰라서 내지 않게.

**대회 주제 적합성**: 공고문 예시 주제 "청년층 자산 형성을 위한 AI 기반 포용적 금융서비스"에 해당. 취준생이라는 소득 공백기 계층의 지출을 정책 매칭으로 줄이는 금융 포용 서비스.

## 2. 문제 정의

- 취준생에게 특화된 정책은 많다(응시료 지원, 면접수당, 정장 대여, 청년수당, 월세지원…). 그러나 이를 **취준생의 현재 행동·일정에 맞춰 능동적으로 연결하는 서비스가 없다.**
- 기존 서비스(청년정책 포털, 고용24)는 **Who you are**(나이·지역·소득) 기반 검색 포털이다. 취준생에게 필요한 것은 **What you're doing**(다음 주 면접, 시험 접수, 이사, 졸업) 기반의 선제적 안내다.
- 정책을 놓치는 진짜 이유는 "몰라서"만이 아니다: **증빙을 못 챙겨서**(면접확인서·영수증), **예산 소진으로 조기 마감돼서**. → 행위 **이전**에 개입해야 한다.

## 3. 서비스 구조

```
[시작] 페르소나 3종(마이데이터 mock 자동 분석) 또는 직접 입력(설문 + 금융정보, 자동기입)
   ↓
[프로필] PROFILE_SURVEY(설문) + MYDATA(RAW) → FINANCE(정책 판정용 금융 피처 15종)
   ↓
[앱 메인] 검색바(AI 질문) · 마이티끌/추천 · 월 달력(일정 등록) · 절약 위젯
   ↓
[일정 → 매칭] "9/18 SKT 면접" → AI 의미 추출 → 정책 후보 → AI 자격 판정 → 혜택 카드
[상태 변화]  "9/25 대전 이사" → 거주지 변경 감지 → 델타 리포트(열리는/사라지는 혜택) → 프로필 전환
[정책 상세]  자세히보기 → AI 자격 판정(가능/확인 필요/미해당 + 근거 + 증빙 안내)
```

기술 스택: Next.js 16(TypeScript) · Supabase(PostgreSQL, Seoul) · Groq LLM(`openai/gpt-oss-20b`) · Vercel(자동 배포·Cron).

## 4. 데이터 설계

### 4.1 프로필 — "두 출처, 하나의 스키마"
| 구분 | 마이데이터로 확인 가능 | 마이데이터로 확인 불가 |
|---|---|---|
| 페르소나(데모) | 표준 규격 mock 거래내역 | 임의 설정값 |
| 실서비스 | 마이데이터 API | 설문 입력 → DB |

- **PROFILE_SURVEY**: 정책 요건 문장에 실제로 등장하는 항목만 수집 (생년월일·병역·거주지·거주시작일·학력·가구·중위소득구간·재산구간·수급이력·자격증)
- **MYDATA_***: API 원천 그대로 저장 (계좌·거래내역·카드·대출·보험·투자 — 업권별 테이블)
- **derive.ts**: 거래내역에서 월평균소득·월세·수급 수당(종료 시점 추정)·취준 지출을 **결정론적 규칙**으로 계산 (LLM 미사용)
- **FINANCE**: 실정책 178건 요건 분석으로 선별한 **정책 판정용 금융 피처 15종** (소득 8·재산 4·부채 2·자격 3). 조사로 발견한 추가 피처: 기초수급·차상위 여부, 원가구(부모) 연소득(무소득 취준생은 부모 소득으로 판정하는 주거금융 특례)

### 4.2 정책 — 전국 커버리지 실측
| 소스 | 건수 | 비고 |
|---|---|---|
| 온통청년 청년정책 API | 2,750건 전수 | 261개 시·군·구 커버, 전 시·도 등장 |
| 행안부 공공서비스(혜택) API | 전체 10,956건 → 취준 관련 592건 | 온통청년에 없는 전국민 대상 서비스 보완 |
| 큐레이션 | 2건 | 국가 API 미등록 지자체 정책 (출처 명시) |
| **합계** | **3,344건** | `policies` 테이블 |

- 행안부 API의 `supportConditions`가 **코드화된 자격조건 50컬럼**(성별·나이 하한/상한·중위소득 구간별 해당 여부·취업상태)을 제공함을 실측 확인 → LLM 없이 규칙 변환 가능
- 2026년 행정구역 개편(전남+광주 통합 등) 명칭 불일치를 발견해 **지역명 정규화 모듈**로 LLM 출력·프로필·설문을 표준명으로 통일

`profile_survey` `mydata_account` `mydata_transaction` `mydata_card_approval` `mydata_loan` `mydata_insurance` `mydata_investment` `finance` `users` `user_calendar` `policies` `profile_changes` `policy_discovery_queue`

## 5. AI 설계 — "필터 → 검색 → 판정" 3단

```
0. 의미 추출 (LLM)   "대전 이사" → 유형 MOVE · 지역 대전광역시 · 키워드 [이사, 주거, 전입, 정착, 월세]
1. 조건 필터 (SQL)   (전국 ∨ 일정 지역 ∨ 거주지) ∧ 나이 ∧ 마감 — 3,344건 → 수십 건, 결정론
2. 관련성 검색       키워드 확장 + 어휘 검색 (v2: pgvector 의미검색 ⊕ RRF 융합)
3. 자격 판정 (LLM)   구조화 프로필 × 후보 → JSON 계약
                     {score, LIKELY|NEEDS_CHECK|UNLIKELY, 근거, 확인필요 항목, 미리 챙길 증빙}
```

- 각 단이 서로 다른 실패를 막는다: 1단은 타지역·나이초과 추천을 100% 차단, 2단은 무관 후보 제거, 3단은 미묘한 자격(중복수급·졸업 N년 이내)과 **설명** 생성
- LLM 규칙: 후보 밖 정책 생성 금지 / 모르는 조건은 추측 대신 NEEDS_CHECK + 확인 방법 / 금액·날짜는 코드 값만 인용 / 60점 미만 미포함
- 기존 RAG 대비: Naive RAG(임베딩→top-k)가 아닌 **메타데이터 필터 + 쿼리 확장 + LLM 리랭킹**의 Advanced RAG 변형. 벡터 검색은 2단 교체분으로 설계 완료(팀원 v2, pgvector + BGE-m3)

## 6. 구현 기능 (배포 완료)

| 기능 | 설명 |
|---|---|
| 랜딩페이지 | 서비스 소개, 디자인 5종 실험 후 확정 |
| 시작 — 페르소나 3종 | 김민지(시험 시즌·서울 중랑구) / 박준호(면접 러시·경기 수원) / 이서연(퇴사 후 전환·구직급여 수급). 마이데이터 분석 연출 → 도출 프로필 카드 |
| 시작 — 직접 입력 | 설문 11항목 + 금융정보 6항목("실서비스에서는 마이데이터 자동 수집" 명시) + ⚡자동기입 → 3개 테이블 저장 |
| 앱 메인 | 검색바 / 마이티끌·추천 아코디언 / 노션식 월 달력 / 절약 위젯(원 2개) |
| 일정 → AI 매칭 | 일정 등록 즉시 관련 정책 최대 3건 + 이유 + 혜택 요약 + 신청 링크 |
| 상태 변화 감지 | 이사 감지 → "거주지를 바꿀까요?" 확인 → 델타 리포트(새로 열리는 혜택 / 떠나면 사라지는 혜택) → 적용 시 `profile_changes` 기록, 이후 매칭이 새 거주지 기준 (졸업·퇴사·취업 유형도 감지) |
| 정책 자세히보기 + AI 자격 판정 | 지원대상·내용·방법·공식 링크 + 판정 배지·근거·확인 필요·증빙 체크 |
| 신규 정책 발견 크론 | 매일 06:00 국가 API 증분 재수집 → 신규 자동 편입 / 웹 발견물은 격리 큐(`policy_discovery_queue`)에 검증 전 보관 |

## 7. 검증 결과 (실측)

| 시나리오 | 결과 |
|---|---|
| 김민지 × 중랑구 응시료 지원 (자격 판정) | LIKELY 80점 — 나이·거주 3년·미취업(단기 알바 인정) 근거 3개 + 증빙 3종 안내 |
| 박준호(경기) × 서울 청년수당 | UNLIKELY 20점 — "거주지가 서울이 아니므로" 정확 배제 |
| "대전 이사" (서울 거주자) | 직접 혜택: 대전청년 월세지원·임차보증금 이자지원 / 새로 열리는 혜택 6건(AI 거점·정장 대여·코업 등) / 사라지는 혜택 4건(서울 청년수당 등) |
| "광주로 이사" | 지역 정규화 후 정상: 광주 주거 3건 + 새 지역 정책 418건 중 6건 선별 |
| "대전에서 자기소개서 준비" | 면접 정장 무료대여 + 대전 청년공간 AI 거점 (범용 키워드 제거 후 농업 정책 오추천 해소) |
| 웹→DB 기록 (로봇 E2E) | 페르소나 시작·직접 입력·일정 등록·이사 적용 — 로컬·배포판 모두 DB 행 생성 확인 |

발견·수정한 오판정 사례(신뢰 설계 근거): ① 알바 소득을 "취업자"로 오판 → 취업상태 필드 추가 + 규칙 ② 범용 키워드로 무관 정책 혼입 → 키워드 필터 + "무관하면 빈 배열" 규칙 ③ 거주지 정책이 후보 수에 밀림 → 일정 지역 우선 조회 ④ 지역명 불일치 → 정규화 모듈 ⑤ gpt-oss 추론 토큰 소진으로 출력 공백 → `reasoning_effort: low` + 재시도.

## 8. 신뢰 설계 (금융 서비스 원칙)

1. **계산은 코드가, 판단은 AI가** — 소득·월세·절약액·자격 하한선은 결정론적 코드. LLM은 후보 내 선택과 설명만
2. **모르면 추측하지 않는다** — null 값은 NEEDS_CHECK + "무엇을 어떻게 확인할지"
3. **출처를 항상 첨부** — 공식 신청 링크, 큐레이션 정책은 미등록 출처 명시
4. **미검증 격리** — 웹·크롤 발견물은 승인 전 추천에 사용하지 않음
5. **LLM 교체 가능 부품** — 환경변수 1개로 모델 교체, 금융 숫자는 LLM 경로를 거치지 않음

## 9. 한계와 로드맵

| 한계 | 대응 (로드맵) |
|---|---|
| 지자체 자체 채널 정책이 국가 API에 미등록 (대전시 청년공간 AI 거점 실사례) | 17개 시도 청년포털 크롤 계층 + 웹검색 발견(CRAG식 fallback) → 격리 큐 → 검증 편입 |
| 추천 탭이 아직 데모 데이터 | 프로필 기반 자동 추천으로 교체 (매칭 엔진 재사용) |
| 검색 2단이 어휘 기반 | pgvector 의미검색 + RRF 융합 + 리랭커 (팀원 v2) |
| eligibility_json 미생성 | 행안부 조건코드(JA) 규칙 변환 + 온통청년 텍스트 LLM 파싱 |
| 마이데이터 실연동 | 표준 규격 준수 mock → 사업자 제휴 시 소스만 교체 (동일 스키마) |

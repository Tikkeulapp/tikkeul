# 취업 후 시뮬레이션 — 설계·데이터 요구사항

> 목적: 취준생이 "취업하면 내 돈은 어떻게 흐르고, 목표(목돈·내집·결혼)까지 얼마나 걸리며, 어떤 제도가 열리는가"를
> 마이데이터 소비·대출 구조 위에 예상 연봉을 얹어 미리 본다. 이사 감지와 같은 **생애 이벤트(취업) → 열리는/닫히는 혜택** 구조의 확장.

## 1. 입력

| 항목 | 형태 | 기본값 | 비고 |
|---|---|---|---|
| 기업 구분 | 선택 (대기업·중견기업·중소기업·스타트업·공기업·공무원·기타) | 중소기업 | 세금 계산(중소기업 감면·공무원연금)과 제도 판정 양쪽에 영향 |
| 세전 연봉 | 직접 입력 (만 원) | 3,600 | 1,000만~10억 |
| 목적 | 목돈 모으기 / 내집마련 / 결혼 | 목돈 | 목돈: 금액 입력(기본 1억). 내집: 권역 7개(서울·수도권·경상·전라·충청·강원·제주) |
| 입사 예정 월 | YYYY-MM | 다음 달 | 도달 시점 계산 기준 |
| 월 카드 소비 | 직접 입력 사용자만 | 60만 | 페르소나는 마이데이터 카드 승인내역에서 자동 집계 |

## 2. 마이데이터에서 읽는 것 (수집 가정 범위)

| 업권 | 테이블 | 사용 필드 | 시뮬레이션에서의 역할 |
|---|---|---|---|
| 은행 계좌 | `mydata_account` | 잔액·유형 | 시작 자산(수시입출금+CMA = 유동, 예·적금 = 저축) |
| 은행 거래 | `mydata_transaction` | 출금 설명·금액 | 월세·통신·보험 등 **고정지출**(2개월 이상 반복), 계좌 기타 소비 |
| **카드** | `mydata_card_approval` | 승인일·가맹점·업종(분류)·금액 | **변동소비** 월평균 + 카테고리 상위 5 (소비습관) |
| **대출** | `mydata_loan` | 유형·잔액·금리·월 상환액 | 대출 상환액 → 지출, 금리 → 상환 우선/저축 병행 판정 |
| 설문 | `profile_survey` | 생년월일·주거형태 | 나이(감면·청년 제도 요건), 월세/본가(세액공제·세대주 요건) |

- 카드 분류: 실서비스는 가맹점 업종코드(MCC) → 서비스 분류 10종(식비·카페·교통·생활·쇼핑·구독·문화·의료·취업준비·기타) 매핑. 데모 mock은 분류를 직접 기록.
- 3개 페르소나에 카드 승인내역 16~21건(7~8월)·대출 0~1건을 추가하고 DB에 시드함(`scripts/seed.mts`).
- 직접 입력 사용자: 카드·고정비 없음 → 카드 소비는 입력값, 대출은 `finance.loans_by_type` 잔액 + 유형별 가정 금리(학자금 1.7 / 전세 3.5 / 신용 5.0%, 60개월 균등).

## 3. 계산 (전부 코드 — `src/lib/simulate.ts`)

1. **세후 월 실수령** — 4대보험(국민연금 4.5%·상한, 건강 3.545%, 장기요양 12.95%, 고용 0.9%) + 근로소득세(근로소득공제 → 기본공제·보험료공제 → 세율표 → 근로소득세액공제) + 지방소득세 10%.
   - 중소기업·스타트업 & 만 34세 이하 → **중소기업 취업자 소득세 감면 90%(연 200만 한도)** 반영
   - 공무원 → 공무원연금 기여금 9%, 고용보험 미가입
   - 부양가족·카드공제 등 미반영 → 화면에 "간이 계산 근사치" 표기
2. **월 지출** = 고정(월세+통신·보험) + 대출 상환 + 변동(카드 월평균 + 계좌 기타)
3. **여유자금** = 실수령 − 지출
4. **시나리오 3종** — 보수(여유 50% 저축) / 기본(70%) / 공격(90% + 변동소비 15% 절감)
5. **목표 도달 개월** — A(1+i)^n + S((1+i)^n − 1)/i = T, i = 연 3.0%/12 (세후 근사)
   - 목돈: T = 입력 금액
   - 내집: T = 참고 주택가격 × (1 − LTV 70%) + 부대비용 3%
   - 결혼: T = 주택 제외 평균 결혼비용 × 본인 부담 50%
6. **대출 판정** — 금리 > 4%(저축 수익률 3% 기준선) 대출이 있으면 "상환 우선", 아니면 "저축 병행"
7. **경고** — 지출 > 실수령, 월세 > 실수령 30%, 20년 초과 등

## 4. 참고값 (`src/data/postjob_reference.ts`, 기준 2025-12)

| 값 | 출처 | 비고 |
|---|---|---|
| 권역별 아파트 중위 매매가격 (서울 9.5억 · 수도권 5.2억 · 경상 3.0억 · 전라 2.1억 · 충청 2.5억 · 강원 2.0억 · 제주 3.3억) | KB부동산 월간 주택가격동향·한국부동산원 통계를 권역 단위로 반올림 | **데모 참고값** — 실서비스 월 갱신 대상 |
| 주택 제외 평균 결혼비용 6,500만 원 | 듀오 결혼비용 보고서(2024) | 반올림 |
| 세율·공제·4대보험 요율 | 2025년 귀속 기준 | 연도 변경 시 파라미터만 수정 |

화면에는 출처·기준 시점을 항상 함께 표시한다. LLM은 이 값을 새로 만들지 않는다.

## 5. 취업 후 열리는 제도 (`src/data/postjob_programs.ts`, 14종 큐레이션)

| 분류 | 제도 | 판정 규칙(요약) |
|---|---|---|
| 자산형성 | 청년도약계좌 | 19~34세 & 총급여 ≤ 7,500만 → 확인 필요(가구소득) |
| 자산형성 | 중소기업 재직자 우대 저축공제 | 중소기업·스타트업 → 확인 필요(기업 참여) |
| 자산형성 | 청년내일저축계좌 | 19~34세 & 월소득 ≤ 250만 → 확인 필요 |
| 세제 | ISA | 누구나 가능. 총급여 ≤ 5,000만 → 서민형 |
| 세제 | 중소기업 취업자 소득세 감면 | 중소기업·스타트업 & ≤ 34세 → 확인 필요(업종) |
| 세제 | 주택청약종합저축 소득공제 | 총급여 ≤ 7,000만 & 세대주 |
| 세제 | 월세 세액공제 | 월세 거주 & 총급여 ≤ 8,000만 → 가능성 높음 |
| 연금 | 연금저축·IRP 세액공제 | 누구나 → 가능성 높음 (공제율 소득별) |
| 연금 | 공무원연금·공제회 | 공무원 |
| 주거 | 청년주택드림청약통장 | 19~34세 & ≤ 5,000만 & 무주택 |
| 대출 | 중소기업취업청년 전월세보증금 대출 | 중소기업 & 19~34세 & ≤ 3,500만 |
| 대출 | 디딤돌 대출 / 보금자리론 | 내집마련 목표 시 소득·주택가격 요건 확인 |
| 결혼 | 신혼부부 특별공급·전용 대출 | 결혼 목표 시 |

- 판정 3단계: 가능성 높음 / 확인 필요 / 요건 미충족(접힘). 근거 문구는 코드에 고정.
- 요건은 공고 요약이며 `asOf` 이후 변경될 수 있음 → "확인 필요" 원칙 유지. ISA 비과세 한도 확대, 중기청 전월세대출 운영 기한 등은 변동 가능 항목으로 명시.
- 다음 단계: 정책 DB(`policies`) 3,344건에서 재직자·자산형성·주거 키워드로 후보를 뽑아 LLM 선별하는 델타(이사와 동일 엔진) 결합, 행안부 데이터 재직자 필터 재수집.

## 6. AI의 역할 (Groq `gpt-oss-20b`, JSON)

- 입력: 계산 결과 요약(실수령·지출·시나리오·대출 판정·열리는 제도 목록)
- 출력: `{summary(3~4문장), priorities[3], cautions[2]}`
- 규칙: 제공된 숫자만 인용, 새 숫자·금리·기간 생성 금지, 제도는 목록 안에서만, 단정 대신 "~로 보입니다"
- 실패 시: 계산 결과는 그대로 표시하고 AI 블록만 "불러오지 못함" 표시 (계산이 AI에 의존하지 않음)

## 7. 화면

- 진입: 앱 우측 원 위젯 아래 **[🎯 취업 후 시뮬레이션]** 카드 → 작은 모달(입력 5항목) → 결과(넓은 모달)
- 결과 순서: 실수령(공제 내역) → 한 달 흐름 막대(고정·대출·소비·저축·여유) + 카드 소비 상위 + 대출 판정 → 목표·시나리오 3장 → 경고 → 열리는 제도 → AI 코치 → 출처·고지

## 8. 한계 (MVP)

- 세금은 간이 계산(부양가족·특별공제 미반영), 주택·결혼비용은 참고값
- 결과 저장 없음(새로고침 시 사라짐) — 다음 단계: `simulations` 테이블
- 정책 DB 연동 미적용(큐레이션 14종만) — 다음 단계: 델타 엔진 결합
- 직접 입력 사용자는 카드·고정비를 추정/입력에 의존

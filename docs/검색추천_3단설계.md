# 검색·추천 3단 설계 — 필터 → 하이브리드 검색 → LLM 판정

> 일정 매칭(`/api/event-match`), 정책 자격 판정(`/api/relevance`), 검색바 채팅 RAG가 공유하는 파이프라인.
> 원칙: **자격의 하한선은 규칙이, 관련성은 검색이, 미묘한 판정과 설명은 LLM이.**

## 전체 흐름

```
사용자 질문/일정 ("9/25 대전 이사")
   │
   ▼ 0. 의미 추출 (LLM 1회) — 유형 MOVE, 지역 대전, 키워드 [이사,주거,전입,정착,월세]
   │
   ▼ 1단. 조건 필터 (SQL, 결정론)
   │    (전국 ∨ 일정지역 ∨ 거주지) ∧ 나이 범위 ∧ 마감 유효
   │    2,750건 → 수백 건 — "자격이 원천 불가능한 건 제외"
   │
   ▼ 2단. 하이브리드 검색 (관련성)
   │    축A 키워드(FTS/ilike): 고유명사·정확매칭 강함 (SQLD, 햇살론유스)
   │    축B 벡터(pgvector+BGE-m3): 의미 유사 강함 (이사↔전입정착)   ← 팀원 담당
   │    RRF 융합 → 상위 15건
   │
   ▼ 3단. LLM 자격 판정 (Groq)
        입력: 구조화 프로필(FINANCE·SURVEY) + 후보 15건
        출력(JSON 계약): score · LIKELY|NEEDS_CHECK|UNLIKELY · 근거 · 확인필요 · 증빙todo
        규칙: 모르면 추측 금지 / 후보 밖 정책 생성 금지 / 금액·날짜는 코드 값만 인용
```

## 각 단이 막는 실패

| 단 | 막는 실패 | 도구 선택 이유 |
|---|---|---|
| 1단 SQL | 타지역·나이초과 정책 추천 | 자격 하한선은 100% 보장 필요 — LLM·벡터는 확률적이라 부적합 |
| 2단 하이브리드 | 관련 없는 후보 혼입 / 표현이 달라 못 찾음 | 키워드↔벡터가 서로의 사각(고유명사↔패러프레이즈)을 커버 |
| 3단 LLM | 미묘한 자격 문제(중복수급, 졸업 N년 이내) + 설명 부재 | 판정 '이유' 생성은 LLM만 가능. 단 후보 내 선택만 |

## 안전핀 (심사 대응 포인트)

1. **LLM은 판정·설명만** — 금액·날짜·자격 하한은 결정론 코드 (환각으로 금융 숫자 생성 불가)
2. **단계별 독립 교체** — 2단을 ilike→pgvector로 교체해도 1·3단 무변경
3. **고정 JSON 출력 계약** — UI·DB(user_policy_matches)·절약 리포트가 동일 구조 재사용
4. 모르는 값(null)은 NEEDS_CHECK + "무엇을 어떻게 확인할지" 안내 (추측 금지)

## 버전 로드맵과 분담

| | 2단 구성 | 상태 |
|---|---|---|
| **v1** (제출용) | LLM 키워드 확장 + ilike | ✅ 구현·배포 완료 (`/api/event-match`) |
| **v2** (팀원) | v1 키워드축 유지 ⊕ pgvector 벡터축, RRF 융합 | 설계 확정, 병행 개발 가능 |

### v2 팀원 작업 스펙
- `create extension vector;` + `alter table policies add column embedding vector(1024);`
- 임베딩 모델: **BGE-m3** (한국어 강함, 오픈소스) — 2,750건 벡터화는 개발 서버 GPU에서 배치 1회
- 쿼리(질문) 실시간 임베딩: Vercel에서 호출할 임베딩 API 결정 필요 (OpenAI text-embedding-3-small ≈ 무시 가능한 비용 / HF Inference 무료 티어)
- 검색 함수 인터페이스(기존과 동일하게): `(keywords[], query_embedding, region, age) → 후보 15건`
- 융합: RRF (k=60), 키워드 순위 ⊕ 벡터 순위

### Chroma가 아닌 pgvector인 이유
- Chroma = 별도 상주 서버 필요 → Vercel(서버리스) 구조와 불일치, 심사 기간 운영 리스크
- pgvector = 이미 쓰는 Supabase에 내장 — 정책 행과 벡터가 같은 테이블, 조건 필터+벡터 검색이 SQL 한 방
- 프로토타이핑은 Chroma로 해도 무방, 프로덕션 반영만 pgvector로

## 재사용처

- 일정 → 정책 매칭 (구현됨)
- 자세히보기 → 자격 판정 (구현됨, 3단만 단독 사용)
- 검색바 "모르는 거 물어보기" 채팅 RAG (예정 — 입력이 일정 대신 자유 질문일 뿐 동일 파이프라인)
- 신규 정책 알림 (역방향: 새 정책 → 기존 사용자 프로필과 매칭)
